# 用户平台并发限制

管理员在「用户管理 → 编辑用户 → 平台并发限制」中配置。用户总并发继续生效，
平台限制按用户 ID 与具体平台合并计算，覆盖该用户的所有 API Key 和分组。

- 留空或 0：没有额外的平台上限，仍受用户总并发限制。
- 正整数：该用户在此平台最多同时运行的请求数。
- 总并发为 0 时，平台上限仍然生效。
- 组合分组按解析后的目标平台计数；Antigravity 和 Anthropic 是不同平台。
- 普通请求和 SSE 沿用用户等待队列；WS 按每轮生成占槽，空闲连接不占生成槽。
- OpenAI Live 会话计入 OpenAI 平台与用户总并发，沿用原有 Live 租约续期和释放。
- 下调上限不终止已开始的请求。后续请求、等待重试、WS 后续轮次使用刷新后的配置。

## 管理接口

现有创建／更新用户接口接受 `platform_concurrency_limits` 对象，例如
`{"openai": 2, "anthropic": 3}`。更新时省略字段保留原值，传 `{}` 清空全部平台限制；
传入对象替换该用户的完整平台配置。平台标识使用项目平台清单，不接受 `composite`。

## 实现与部署

配置存储在 `users.platform_concurrency_limits`（JSONB），由迁移
`312_user_platform_concurrency.sql` 添加，默认 `{}`。鉴权快照包含此字段；更新后
通过用户缓存失效及数据库 outbox 刷新。平台限制随原有鉴权查询读取，不单独查询数据库；
等待重试复用鉴权缓存，缓存失效或未命中时仍可能回源数据库。

Redis Lua 同时检查并占用用户总槽和平台槽，失败不占用其中任何一个。平台计数
在未设置上限时也保留，以便之后设置上限时包含在途请求；释放使用同一请求 ID。
平台等待沿用现有用户等待名额。请求槽的过期与异常回收遵循现有用户槽 TTL。

所有参与同一限流范围的实例必须使用同一 Redis，并升级到支持此功能的版本。
首次升级时应先停止接收新流量并排空旧版本请求，再启用平台上限；旧版本及其
已经建立的请求不会写平台计数。回退版本前清空平台上限。此迁移为新增列，
回退应用时可以保留数据库列。

regional SQL 并发模式暂不支持该功能：管理员接口拒绝配置正数平台上限，
切换到 regional 模式时若存在正数配置，启动检查会明确报错。

## 注册／首次绑定的默认配置

「系统设置 → 用户 → 认证来源默认配置」支持为钉钉等各个认证来源配置平台并发，
与用户编辑页使用相同的平台清单。启用来源默认配置后，首次注册将这些上限写入用户；
启用首次绑定发放后，首次绑定仅覆盖填写过的平台，重复绑定不重复应用。

- 留空：首次注册不设置该平台上限；首次绑定保留用户已有值。
- 0：取消该平台的额外上限；正整数：设为该平台上限，仍受用户总并发限制。
- 原有首次绑定的余额、总并发继续累加发放；平台并发作为上限，不累加。

管理设置接口使用 `auth_source_default_<source>_platform_concurrency_limits` JSON 对象。
省略或 null 保留设置，`{}` 清空该来源的默认平台配置，不修改现有用户。
默认配置存入 settings，无需新增数据库迁移。

当前 Live 仅支持 OpenAI，因此直接将现有 Live 用户计数计入 OpenAI 平台。
若以后增加其他平台的 Live，需要同步扩展该计数规则。
