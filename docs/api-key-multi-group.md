# API Key 多分组与上游渠道声明

开发基线：`ranxi2001/sub2api` 的 `production`，`ae964909e83d83ae068658a413b84e5961df7b13`（2.12.3）。

用户创建或编辑 Key 时，可按扣费优先级添加最多 5 个有权使用的分组，并通过上移、下移调整顺序。默认只使用所选分组，不自动添加其他分组。旧 Key 和旧客户端的 `group_id` 继续有效；新客户端用 `group_ids` 按优先级提交完整列表。两者同时出现时，`group_id` 必须与数组首项一致。更新时省略 `group_ids` 表示不修改列表；显式提交空数组且不传 `group_id` 表示解绑；单独更新 `group_id` 表示替换为单分组。已有超过 5 组的 Key 不自动裁剪，仍可请求；在前端编辑保存前需主动移除多余分组。

每个新请求按保存的顺序检查分组，跳过停用、无权限、订阅过期、订阅日/周/月额度耗尽、模型受限或无可调度账号的分组。第一个满足条件的分组承担请求，不再比较倍率或负载，也不因为繁忙切换扣费分组；繁忙时沿用该分组的排队机制。余额分组按现有余额准入阈值检查账户余额。例如顺序为「订阅 A → 订阅 B → 余额 C」时，优先用 A，A 额度耗尽后用 B，两者额度均耗尽且余额可用时用 C；订阅额度重置后，下一个请求恢复优先用 A。订阅额度可用时不要求账户有余额。

最终费用仍按所选分组的模型/渠道定价、适用倍率和实际使用量计算，沿用现有计费路径。额度与可用性是请求开始时的快照，最终资金准入、并发抢占、上游重试和流式行为由现有网关处理。本功能在请求开始时选择分组，不新增发送请求后的跨组重试；正在执行的请求或已建立的 WebSocket 不因配置变化中途改变计费归属。排队和 WS 重新鉴权会核实所选分组仍绑定且有权限。

此版本的自动选择用于普通主站网关；使用区域本地鉴权快照的网关会对多分组请求返回明确的不可用错误，避免绕过其权限与资金边界。生产启用前须评估实际网关部署方式。

## 查看上游多个分组的倍率

账号管理的「分组」列是本地账号加入的分组。「上游渠道声明」列的数据来自该账号所用上游 Key 的 `/v1/sub2api/billing`，两者并非同一份分组配置。

单分组 Key 继续返回 schema v1。多分组 Key 返回 schema v2：

```json
{
  "object": "sub2api.key_billing",
  "schema_version": 2,
  "billing_scope": "token",
  "billing_mode": "multi_group",
  "groups": [
    {
      "group_id": 1,
      "group_name": "Economy",
      "platform": "openai",
      "status": "active",
      "object": "sub2api.key_billing",
      "schema_version": 1,
      "billing_scope": "token",
      "group_rate_multiplier": 0.18,
      "resolved_rate_multiplier": 0.18,
      "peak_rate_enabled": false,
      "effective_rate_multiplier": 0.18,
      "observed_at": "2026-10-20T00:00:00Z"
    }
  ],
  "min_rate_multiplier": 0.18,
  "max_rate_multiplier": 0.18,
  "observed_at": "2026-10-20T00:00:00Z"
}
```

每个分组沿用 v1 的倍率字段，含可选用户专属倍率和高峰时间/时区。只返回 Key 绑定且用户仍有权使用的分组；停用状态保留显示。顶部范围反映声明中各分组当前 token 倍率，并不承诺某个具体模型或下一次请求的价格。

v2 顶部没有 `resolved_rate_multiplier` 或 `effective_rate_multiplier` 单值，以免旧下游把任意分组的价格同步成固定成本。探测端逐组校验、仅保存白名单字段，展示倍率范围和可展开的分组名称、倍率明细；每组按自己的时区刷新当前高峰倍率。过期或失败标记继续保留，旧明细可供参考。

识别到多分组声明后，停止自动回写单一账号倍率和成本倍率，保留管理员原有设置。保存的自动同步偏好不被改写；以后上游恢复单分组声明时可恢复原同步行为。管理员需要手动编辑倍率时，可关闭原有的同步开关。

上游须实现该多分组声明协议才能提供完整清单。仅升级消费端无法从旧的单分组声明推断其他分组名称和倍率；未支持、失败和过期状态也不会被本地账号分组拼成上游结果。

## 迁移与验证

迁移 `291_api_key_groups.sql` 新增额外分组关联表，保留 `api_keys.group_id` 作为旧客户端绑定。`308_api_key_group_priority.sql` 新增 `priority` 列保存附加分组顺序；旧数据沿用此前返回的顺序（主分组在前，附加分组按 ID），不删除任何绑定。Key 创建/编辑与关联更新使用同一事务；列表筛选、缓存失效和管理员分组迁移覆盖额外绑定，移除主分组时按优先级提升下一组。升级需运行新迁移，应用启动时会自动执行；旧迁移不变。

相关用例覆盖顺序保存与调整、订阅额度依次耗尽后切换余额、繁忙时保留优先级、权限撤销、请求快照隔离、绑定事务回滚及迁移幂等性。前端覆盖默认单分组、去重、5 组上限、排序与移除后的提交，以及旧 Key 超限时完整显示并提示处理。
