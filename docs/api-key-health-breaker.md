# API Key 账号滑动窗口健康熔断

在账号的新增、编辑页面开启「API Key 健康熔断」，也可以选中多个 API Key 账号批量修改。默认关闭；开启后的默认参数为窗口 N=100、失败阈值 M=10，允许配置 `1 ≤ M ≤ N ≤ 10000`。不依赖账号池模式，不改变各上游原有的流量分配策略。

## 样本与触发

按单个账号的实际上游调用结果统计，重试分别计数。例如首次失败、重试失败、再次重试成功，写入 `[失败, 失败, 成功]`。HTTP 状态失败在收到响应头时结算；响应体和流的结果在得到相应证据时结算。并发请求按结果被记录的顺序入窗。窗口未满时也判断，累计失败达到 M 次立即熔断。

以下情况计入失败：

- 上游 HTTP 400、408、429、5xx。
- 连接失败、上游超时，包括等待响应头、首个有效输出及流读取超时。
- 明确的上游流中断、无完成事件便结束的 SSE。
- HTTP 200 中结构化的 `error`、`response.error`、`status: failed`，以及 SSE / WebSocket 中的错误事件。

正常完整响应或已确认的流完成事件计入成功。客户端主动取消、本地限流或准入拒绝不计入失败；401、403 等继续执行现有凭证或错误策略，不额外记为健康样本。无充分证据的提前关流不推定为成功。响应检查有大小上限，不保存用户正文或生成内容。

覆盖实际转发的 HTTP / SSE 和 OpenAI 原生 WebSocket。WebSocket 每次 `response.create` 单独计数，前台建连失败计入失败，成功握手不算一次成功请求。HTTP 桥接仅在实际 HTTP 发送处记一次。后台账号测试、模型发现、额度探测、连接池保活不写入该窗口；传输层在尚未发出 HTTP 请求前的内部 TLS 握手补偿不另建请求样本。

## 暂停与恢复

| 自上次阶梯重置以来的熔断次数 | 暂停时长 |
| --- | --- |
| 1 | 15 分钟 |
| 2 | 30 分钟 |
| 3 及以后 | 60 分钟 |

触发后清空窗口，标记整个账号「临时不可调度」。到期后按现有调度机制恢复，新的调用从空窗口开始。熔断前尚未结束的请求结果不会写入下一轮窗口，也不会延长本轮暂停或重复提升阶梯。已经发送的请求继续执行，新的发送会检查熔断状态。

只有距上次熔断满 6 小时、且这段期间有正常成功请求，才重置暂停阶梯；一直闲置不能重置。阶梯重置在满足条件后的下一次有效样本结算时执行，不清空当前滑动窗口。每次再次熔断都会重新开始这段观察期。

账号测试成功不会提前解除健康熔断，也不作为健康成功样本或重置阶梯。管理员在临时不可调度详情中执行「恢复账号状态」可主动解除暂停并清空窗口及阶梯。修改 N/M 会清空旧窗口，保留已有暂停和阶梯；关闭开关停止后续计数，已有暂停需到期或手动恢复。

## 存储与现有策略

配置存入账号 `credentials.api_key_health_breaker`，无需数据库迁移：

```json
{
  "api_key_health_breaker": {
    "enabled": true,
    "window_size": 100,
    "failure_threshold": 10
  }
}
```

Redis 以账号为单位保存有界样本列表和阶梯，通过原子脚本保证多实例计数一致，使用 Redis 时间计算暂停及 6 小时观察期。状态不因闲置自动过期；应用重启不会自行重置，Redis 数据丢失会丢失计数和阶梯，已写入数据库的暂停仍会保留。

触发时同步现有数据库临时不可调度字段、调度缓存及进程内阻断。详情显示触发时的样本数、失败数、阈值和熔断次数。如果数据库写入失败，Redis 仍阻止实际发送，下一次发送前会重试持久化。Redis 计数不可用时记录日志并放行，避免缓存故障使全部上游被阻断。

开启该功能的账号不再进入旧的全局 OpenAI API Key 健康熔断，避免重复计数。现有 429、凭证错误、自定义临时不可调度等策略继续生效；多个暂停重叠时沿用现有只延长、不缩短的规则。
