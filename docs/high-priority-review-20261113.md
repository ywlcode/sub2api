# 高优先级审查修复与验证

基线：`dev-ywlcode` 的 `caf94ba7d`。本次范围为审查报告的高优先级第 1–6 项；未部署到生产。

## 核实结果与改动

| 问题 | 核实结果 | 修复 |
| --- | --- | --- |
| 事件上传受每 5 秒 128 条限制，诊断积压拖住续租 | 成立；匿名请求也能制造上传事件 | 权限同步与事件上传分开；上传连续处理，每批最多 512 条，账单优先并给诊断留份额；匿名诊断只保存在从站。控制请求仅携带最多 4,096 条已尝试上传的账单 ID，诊断积压不扩大续租请求。 |
| 一个坏事件导致整批反复失败 | 成立；不存在的订阅/账号、非法账单时间均可触发 | 每个事件使用独立保存点；确定性错误持久隔离并回传拒收原因，其余事件正常入账。数据库连接和超时等不确定错误仍重试。 |
| 账单提交后 Redis 失败导致同步失败 | 成立 | 已提交账单与回执照常确认；缓存失效失败记录告警，由持久计费恢复 worker 补偿。配置和价格导出在快照提交前完成。 |
| 每轮全表导出、单次响应 32 MiB 上限、待确认账单导致整表重装 | 成立 | 主站维护事务内变更集合和持久投影，普通变化按行查询；用户/Key/订阅按授权范围过滤；大快照分页。从站仅更新变更行和未结账单的归属行，纯金额变化不清空全部请求配置缓存。 |
| 客户端错误触发共享账号健康熔断 | 成立；含 4xx、结构化流错误、GET 任务轮询和上传前网络故障 | 这些结果按中性处理。HTTP 5xx、上传后的连接故障及真实流中断仍计入失败；现有限流、凭证处理和重试策略继续生效。 |
| 默认保留期缩短与去重记录提前删除 | 成立，但管理员显式配置的短期限应保留 | 恢复使用记录 90 天、去重 365 天、错误/连接/耗时 30 天默认值；迁移只补旧设置中缺失的字段。去重保护取运维期限、使用记录期限和服务端去重期限的最大值；使用记录无限保留时去重也不自动过期。 |

## 验证

- 后端全量单测、构建、golangci-lint、针对健康熔断与站点同步的竞态测试通过；前端构建和受影响组件测试通过。
- 独立 PostgreSQL 实验验证旧设置迁移、显式设置保留、实际清理边界、重复账单防重、备份恢复后的数据及索引一致性。
- 主从存储集成测试覆盖坏事件隔离、订阅/账号缺失、Redis 回调失败、确认丢失重发、拒收账单余额保留、撤销授权、北京时间订阅周期和耗时关联。
- 1,000,100 条合成诊断积压不增加控制请求的账单 ID 数；1,600 条有效诊断连续分 4 批完成导入。本机数据库实验耗时约 3–5 秒，不能视为跨地域生产吞吐承诺。
- 5,000 用户样本中只导出 2,500 个获授权 Key；约 38.9 MB 的快照分 20 页完成；随后修改一个余额只下发一行，未改用户的数据库行版本不变。主站重启后仍能使用原增量游标。
- 两套 Docker 站点通过 `protocols`、`policy`、`delivery`、`network`、`lifecycle` 五组回归：三协议及流完成事件、原 Key/gzip 转发、权限与额度变更、断网积压、丢确认、进程重启、错误令牌/身份/数据库版本、独立站模式。
- 网络实验包括 4 秒控制面延迟、60% 随机丢包加 140 ms 延迟、完全断网。权限租约到期拒绝新请求；已放行的国内流可完成；恢复后自动补账，测试账单与主从余额一致。

复现入口：`deploy/tests/site-lab/README.md`、`tools/retention-test/README.md`；新增存储边界测试位于 `site_resilience_integration_test.go` 和 `retention_upgrade_integration_test.go`，使用 `integration` 构建标签。

## 升级与边界

- 主从控制协议升级为 v4，两端需要匹配版本；主站反向代理需允许 `/internal/sites/sync` 和 `/internal/sites/events`。升级间隙从站仍遵守 15 秒权限有效期。独立站点不使用这些接口。
- 拒收账单在两端保留载荷、原因和回执，并继续保留从站原扣款覆盖；拒收不代表成功计费或自动退款，需要管理员核对处理。
- 账号授权、分组绑定等改变可见范围的操作仍会重建授权投影；首次分页安装允许最长 2 分钟，完成后必须取得新鲜租约才能服务。持续同步失败时不会放宽 15 秒有效期。
- 账单上传等待快照确认的窗口为 4,096 条；达到窗口后等待下一次核对。数据库与网络仍决定实际容量，未据此承诺十万用户或任意 QPS。
- 保留期迁移不恢复已经删除的数据，也不覆盖已有显式短期限。关闭自动清理仍表示保留数据，需按实际磁盘容量配置策略。
- 审查报告的中低优先级事项不属于本次修复范围。
