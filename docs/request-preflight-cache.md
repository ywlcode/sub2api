# 请求转发前的配置缓存与账号复用

这批优化不改变计费准入或并发计数，不跨请求缓存最终调度结果。

## 分组配置

网关注册分组路由时，让共享的 SchedulerSnapshotService 使用 APIKeyService
已有的分组配置缓存。鉴权、多分组预筛和调度的 Lite 配置读取共用 30 秒缓存及
现有失效通知；通知未连接时回源。区域网关仍优先使用本地认证快照。

每次读取返回请求独占的配置副本，复合分组按实际分组 ID 分开读取。

## 一轮选号中的账号复用

仅 legacy 负载选号的一次调用创建临时上下文。账号完成原有完整数据库复检后，
同一轮最终 hydration 可以复用该完整对象，省去再次读取并解码 Redis 账号快照。
仍执行最后的暂停状态检查；申请并发槽位的实时检查保持原样。

身份通过对象指针匹配，不因 ID 相同就复用。重试、重新选号、跨组和排队重入不共享
这份上下文。多个候选分别保留本轮已复检的对象，避免排序后选中的账号因不是最后
检查的候选而再次加载。区域快照调用不使用数据库对象替代区域权限。

## 安全处罚配置：按变更失效

首次读取后在内存中保留，不再每秒过期。关闭功能的配置也缓存。缓存仅在失效
订阅就绪时使用；断联回源，重连清空。并发冷加载合并为一次查询，取消的调用方
可以及时退出，查询不持缓存锁。刷新失败不会沿用旧权限。

迁移 `337_security_penalty_config_invalidation.sql` 给 settings 增加触发器，覆盖：

- `security_penalty_config`
- `risk_control_enabled`
- `cyber_policy_user_allowlist`

新增、删除、实际值变更在同一事务中写入已有 auth_cache_invalidation_outbox；
更新相同值不写通知，回滚同时撤销通知。这也覆盖直接 SQL 修改及后台所有写入口。
队列使用保留的 SHA-256 标识，符合现有 CHAR(64) 约束，不含配置内容或凭据。
现有 worker 发布到共享 Redis 订阅，失败会重试，并保留既有延迟安全重发。
SaveConfig 提交后还会立即使本实例缓存失效，并尝试直接通知其他实例。

这是变更驱动的最终一致性，不是跨实例同步屏障：持久化投递通常由现有 500ms
轮询触发，Redis 故障时按已有退避策略恢复。已进入执行的请求不会被追溯撤销。
部署必须包含迁移 337 和原有通知 worker、订阅；启动或迁移失败不能跳过。

## 验证与收益边界

专项测试验证配置隔离、修改失效、两实例同步、并发冷加载、取消和旧刷新竞争；
数据库集成测试验证触发器的事务语义及通过真实 Redis 投递后的缓存重载。

计数测试中，100 次已预热的分组配置读取没有额外回源；100 个并发安全配置请求
合并为一次查库；OpenAI/DeepSeek 的正常 legacy 批量选号每轮账号快照读取从两次
减到一次，完整数据库复检保留。以上是访问次数，不能换算为线上 TTFT 降幅。
