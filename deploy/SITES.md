# 主站、内网从站、主站无从站

三种模式共用 Sub2API 程序，配置为 `site.mode`：

| 模式 | 配置值 | 行为 |
| --- | --- | --- |
| 主站无从站 | `standalone`（默认） | 原有完整站点，不开放从站同步接口 |
| 主站 | `primary` | 原有完整站点，向配置好的从站发布权限和路由，接收用量及诊断数据 |
| 从站 | `secondary` | 国内模型本地鉴权、路由和计量，其他请求保留原 Key 转发主站，不提供管理后台 |

当前部署分工为 boscserver 使用 `primary`，ecosserver 使用 `standalone`，内网站点使用 `secondary` 并与 boscserver 配对。两台公网服务器的用户、余额与订阅账本独立，从站不会自动切换到 ecosserver。主站必须独立提供现有服务，从站未配置、离线或崩溃不构成主站模型请求的依赖。

## 数据与请求路径

每个从站 ID 当前运行一个服务进程。从站需要自己的 PostgreSQL、Redis 和数据目录，不能连接主站数据库或共享主站 Redis。当前实现复用完整网关及数据库结构，以保留三种协议、火山兼容、权限、订阅、计费行为；不是只运行一个无数据库代理。

在主站的账号创建/编辑页面，为持有独立 API Key 的账号开启 **允许从站直接处理**（默认关闭）。该开关授权已配对的从站取得账号凭据并处理其支持的模型；无需额外维护账号 ID 或模型分流清单。它是额外处理权限，**主站直接收到请求时仍可正常调度该账号**，开关不会修改账号状态、调度开关或主站分组绑定。主站无从站模式下也不影响原有请求处理。

从站根据已同步账号的模型映射、默认模型、通配模式以及当前 Key 所属分组和组合路由判断处理位置；匹配后继续走现有本地网关：鉴权、IP 限制、Key 与分组权限、余额/订阅/Key 额度检查、本地上游调度、协议处理、用量计算。开关本身不会赋予用户调用权限。账号保存后在下一轮同步生效，正常约 5 秒，无需重启主从站。关闭开关后，新请求改为转发主站；已放行的请求可以完成，撤销前的账单仍能补交。影子账号和 OAuth 账号不支持此开关。

其他模型由反向代理转发主站：原用户 Key 保留，JSON 正文达到 1 KiB 且 gzip 压缩有效时使用 gzip；已有压缩正文保持原编码。主站完成鉴权及计费，从站不重复生成此类请求的正式账单。SSE 及时 flush，WebSocket 升级整体转发主站，从站不解析 WS 帧，因此国内请求应使用 HTTP 三协议入口。

从站本地鉴权缓存 Key、用户、分组和模型权限配置，TTL 为 30 秒，最多 2,048 条，缓存内容合计最多 16 MiB；不保存原始 Key。每次鉴权及并发准入复核仍通过一条轻量 PostgreSQL 查询读取本地副本中的余额、Key 已用额度、到期时间及禁用/删除状态，不以缓存代替实时额度检查。权限配置同步在数据库提交前后主动失效缓存，并阻止旧查询回填；安装期间回退完整实时查询，普通心跳和纯用量同步不清空身份缓存。订阅用量、计费、并发槽位及 20 分钟主站租约继续使用原有检查。

鉴权数据库查询上限由 `api_key_auth_cache.lookup_concurrency` 控制（默认 64）。主站、独立站及从站达到查询上限后，均最多允许额外 512 个鉴权操作等待，最长 5 秒；调用方取消或更短的准入超时会提前结束等待，队列已满或等待超时返回 503。主站冷缓存下不同 Key 的突发请求可短暂排队，不必增加数据库并发；L1/Redis 缓存命中不进入此队列。这不是用户/账号并发额度，也不延长主站配置租约。

从站每次鉴权数据库读取另有最长 5 秒的上限，覆盖热缓存后的实时余额查询及同步安装期间绕过缓存的读取；更短的调用方超时优先。数据库锁阻塞到期返回 `503 API_KEY_AUTH_UNAVAILABLE`，不使用旧余额放行。该上限只覆盖鉴权读取，不会取消已准入的模型流。

从站每 **5 秒**同步一次。首次全量、后续返回行级 diff（包括删除）；主站进程重启保留数据库中的增量游标；游标或配对配置不匹配时返回全量，分多页传输。配置与事件使用独立的固定字段契约，不再按整张物理表的列结构判定兼容。可选字段变化需按下文升级约定分类、补齐和验证；破坏性语义变化不能直接忽略。

每次同步成功安装后产生 **20 分钟（1,200 秒）**有效期，起点是该次请求发出时间，使用本进程单调时钟。失败、错误响应、安装失败均不续期。首次同步前、重启后未同步、到期后，从站所有新的模型请求返回 **503**（包括转发主站的 GPT 请求）。`/health` 保持存活，`/readyz` 表示同步就绪。已放行请求可继续完成，后台持续尝试恢复同步，不存在额外离线宽限期。断连期间主站停用 Key、撤销账号授权等变化，最迟在这次有效期结束时由从站停止接受新请求；主站自身服务不依赖从站租约。

单纯租约过期或同步请求失败不会清空配置基线和增量版本号。主站恢复后，未重启的从站继续获取断连期间变化的行，同一行多次更新只传最新投影；无需因为过期而重新下载全部配置。首次启动、从站重启、版本/配对配置不匹配或安装失败后才需要全量恢复。主站只重启进程且保留数据库和配对配置时，仍可继续增量。

国内请求的用量通过原有持久计费日志落盘，并与本地扣费、上报 outbox 在同一事务提交；已识别 Key 的错误及连接诊断记录在写入时进入 outbox，未鉴权请求的诊断仅保存在从站。主站使用事件 ID 和账单幂等键去重，消费与确认记录在同一事务提交。未确认消费在安装主站快照后重新覆盖到本地余额/额度。确认使用具体事件 ID，避免并发提交、丢失响应导致跳过消费或重复扣费。主站延迟收到订阅用量时按原记录时间及北京时间日/周/月边界入账，不占用已经进入的新周期。这里的原记录时间沿用网关生成用量记录的时间；不是重新定义为请求开始时间。计价沿用现有网关，已生成的账单金额在补报时不重新定价。从站缺少 usage 或定价时会持久记录 `billing/site_usage_unsettled` 并上传供核对，不生成虚假的零费用成功账单；此类记录本身不表示客户端收到 HTTP 错误，也不能在没有可靠用量时自动补算费用。

原有账号/用户/Key 并发与 RPM 在各站本地执行，**不是跨站强一致全局并发上限**。余额、额度存在同步窗口，允许短时间超额；未完成请求的最终费用也可能在之后才入账。

主站下发账号凭据、权限投影和有效价格目录。用户 Key 使用每个从站独立 HMAC 投影，不下发可复用明文 Key；用户登录密码、TOTP、支付配置及未授权账号的凭据不下发。同步接口仅供受信从站，持有配对 token 的从站能够代表主站执行国内调用和提交计费。使用 HTTPS 及独立的随机 token，配置文件按密钥文件管理。

## 请求配置同步范围

账号的 `credentials.upstream_transport_cooldown` 是可选配置，随获准账号的 credentials 同步，控制持续性网络故障直接触发的暂停。缺失时沿用开启、10 分钟；可关闭或将 `duration_minutes` 配置为 1～1440。它不修改健康熔断、HTTP 错误规则、余额检测、人工禁用或并发限制。关闭只阻止新增的网络暂停，不清除已经产生的暂停。旧版本从站忽略此键并继续原有 10 分钟行为；主站先升级时可正常同步，需从站升级后才会执行新设置。它不涉及权限或计费字段，不改变同步协议版本或数据库结构。

Anthropic/Bedrock 路径原有的直连池模式豁免仍保留：`pool_mode_retry_status_codes` 包含 503 时，网络失败继续使用原有请求重试策略，不直接暂停账号。

控制协议为 v6；配置、事件各自使用稳定契约标识，主站另外兼容已验证的旧 v6 schema。固定字段见 `repository/site_contract_fields.go`，策略见 `service/site_policy.go`、`config/site_gateway_fields.go`；不依赖在每个管理接口中发送通知。

- 固定业务表投影（完整清单见 `site_store.go`）：用户与并发/RPM/平台限制、Key 与 IP/模型限制、分组与个人覆盖、订阅与实际额度、获准账号与模型映射、组合路由、渠道计价与峰谷时区、错误透传、账号引用的 TLS 指纹等。
- 全局请求设置（以 `SiteSettingKeys` 为准）：协议转发、客户端兼容、默认/回退模型、重试与冷却、调度策略、搜索模拟、错误采集等。账号状态还合并性能监控和 AI 运维的暂停结果；暂停控制器和任务本身仍留在主站。
- 明确列出的网关配置及有效计费/额度默认值：请求体和上游响应限制、流超时、重试预算、请求协议策略、最低余额预留、请求中资金预留、Gemini 额度默认值等。复制主站实际加载的值；主站 YAML 修改仍需按既有方式重新加载/重启，随后从站可自动接收。
- 有效价格目录，以及获准账号在配置的质量窗口内完成的轮次摘要（旧版兼容投影仍采用原 7 天摘要）。质量任务、原始检测内容不下发；从站延迟、错误率、连接和负载仍按本地链路采集。

按当前用途，从站只处理开源模型，**安全审计、内容审核、安全处罚规则及处罚状态不下发，也没有新增安全事件回传协议**。用户由管理员停用后的普通 `users.status` 仍属于鉴权数据，照常同步。GPT、Claude、Grok 等未授权本地账号的请求继续交由主站。

账号的组绑定、Key 模型映射、渠道模型别名和组合路由参与位置选择；位置判断后仍经过原有网关的完整授权与调度。仅靠客户端检测才确定的分组 fallback、无法从已授权账号直接判断的请求仍可能交主站处理，不承诺所有复杂回退场景都在从站执行。

登录注册、密码/TOTP/JWT、支付/通知、后台页面、全局定时任务、自动授信的执行等留主站；从站每日清理仅处理本站历史。本地站点身份、数据库/Redis、可信代理链、连接池、worker/队列和存储路径留本站。搜索模拟的主站 `proxy_id` 被清除，从站走自己的直接网络；如供应商要求专用代理或国内不可达，需要另行配置网络，不能复制一个无对应对象的代理 ID。异步图片任务、插件安装/票据、浏览器与 BPS 等专项能力不属于本次开源文本模型从站范围，不为它们复制主站存储、任务控制器和密钥。

安装配置后同步刷新请求缓存、优先级调度规则、Ops 采集规则、搜索客户端、错误透传、TLS 与渠道缓存；请求体限制也从当前配置读取。安装或依赖刷新失败，不续租并关闭就绪，下一轮强制全量恢复。只有余额/用量变化时，不重复构建搜索和 TLS 等配置依赖；无变化心跳不重建这些缓存。

## 增量与每轮数据量

每 5 秒发起一轮，**首次、从站重启或版本不匹配时全量，之后传行级增量（含删除）**。只修改用户并发时发送该用户的一行，不发送全部用户。JSON 内某个字段变化会发送该行完整投影；有效网关默认值和价格目录各是一个合成对象，改变其中内容会发送该对象。

主站通过事务触发器维护每个从站的变更集合和持久投影。导出期间只读取变更集合和业务数据，不锁住扣费触发器；发布后用短事务和 `SKIP LOCKED` 清理本次读到的精确版本，较新的修改和未提交事务留给下一轮。多个主站实例通过独立的发布锁串行化同一从站的导出。余额、Key、订阅等常见变化只读取对应行；账号授权、分组绑定等影响授权范围的变化会重建授权投影。用户、Key、订阅和个人额度仅包含能访问已授权账号分组的用户，未授权账号凭据不下发。全量快照每页通常不超过 2 MiB 或 1,024 行；单条较大配置独立成页，单条上限 30 MiB。跨页期间投影版本变化时重新开始，不能混装不同版本。

从站日志 `site synchronization completed` 每轮记录：

| 字段 | 含义 |
| --- | --- |
| `full`, `rows` | 本轮全量/增量、下发行数（含删除） |
| `events`, `pending` | 控制请求中的事件数（v6 为 0）、本轮待核对账单 ID 数 |
| `upload_json_bytes`, `upload_wire_bytes` | 从站到主站，压缩前/gzip 后正文大小 |
| `download_json_bytes`, `download_wire_bytes` | 主站到从站，压缩前/gzip 后正文大小 |
| `duration_ms` | 本轮采集、传输、安装总耗时 |

字节统计不含 HTTP 头、TLS/TCP/IP 开销和重传。控制请求只带版本和最多 4,096 个已尝试上传的账单 ID 及内容摘要。事件由独立上传循环连续发送，每批最多 512 条，并按 32 MiB 上限缩小批次，账单优先且为诊断保留份额。等待余额快照确认的账单达到 4,096 条时暂停增加新账单上传，诊断仍可上传；下一轮同步核对后继续。诊断积压不增加控制消息大小。上述每轮字节统计仅统计配置同步，不包含独立事件上传。

本机可复现测试 `test_config_sync.py` 验证配置增删、并发值、主站有效默认值、三协议、暂停/恢复、安全配置排除，并记录小样本与千用户样本的实测字节数。数值应结合当次用户/Key/账号/价格条数解读，不能当生产库的固定大小。

## 主从站认证

所有同步均由从站主动向主站发起，主站不需要连入公司内网：

1. 每个从站使用独立随机 token（至少 32 字符，建议 `openssl rand -hex 32` 生成），放在双方配置中，不使用管理员登录 token 或用户 Key。
2. 主站校验 `Authorization: Bearer <token>`，将其绑定到配置中的从站 ID；携带别的从站 ID 会拒绝。允许下发的账号由主站账号配置开关决定。
3. 从站校验 HTTPS 证书与域名，首次成功安装后将主站 ID 固定在本地数据库，之后拒绝身份不匹配的主站。同步请求不跟随 HTTP 跳转，避免泄露配对凭据。
4. 这不是双向客户端证书（mTLS）。主站通过配对 token 验证从站，从站通过 HTTPS 验证主站。`allow_http` 仅用于已另行加密的私有隧道或本地测试，生产公网保持 `false`。
5. 撤销从站时从主站 `peers` 移除并重载部署配置；从站最迟在最后一次成功同步的请求发出起 20 分钟后停止新请求。轮换 token 需更新两端，会重新生成用户 Key 的 HMAC 投影；同步成功前保持关闭。更换主站身份需使用新从站数据库，不能靠修改 ID 绕过绑定。

GPT 等透传请求仍用用户原 Key，配对 token 不附加到模型请求中。配对 token 不适合交给普通用户，它授权从站取得国内上游凭据并提交账单。

## 配置示例

在 boscserver 原有配置中增加（示例 ID、账号号、token 需替换）：

```yaml
runtime:
  role: full
site:
  mode: primary
  id: bosc
  peers:
    - id: office
      token: "REPLACE_WITH_UNIQUE_RANDOM_TOKEN_AT_LEAST_32_CHARS"
      base_urls:
        54: "https://ark.cn-beijing.volces.com/api/v3"
```

先在主站账号 54 开启“允许从站直接处理”。`base_urls` 是可选的、此从站专用上游地址覆盖，不能单独授权下发账号。若主站账号指向美国 go 中转，必须在这里改成国内直连地址。覆盖会清除该从站账号继承的 `api_base_urls`，由现有协议选择逻辑推导；火山 Messages 自动使用 `/api/compatible/v1/messages`。国内账号的美国代理 `proxy_id` 不会下发使用。账号原有火山兼容开关及模型映射保持主站配置。

从站先用原部署方式初始化一套独立 PostgreSQL/Redis；允许只有自动安装创建的管理员，不能含其他用户、Key、账号或账单。挂载自己的持久目录和 `config.yaml`：

```yaml
runtime:
  role: full
site:
  mode: secondary
  id: office
  primary_url: "https://YOUR_BOSC_ORIGIN"
  token: "REPLACE_WITH_THE_SAME_OFFICE_TOKEN"
  allow_http: false
```

简单字段也可以用 `SITE_MODE`、`SITE_ID`、`SITE_PRIMARY_URL`、`SITE_TOKEN` 配置；主站 `peers` 推荐使用 YAML。从站不能启用 simple 免计费模式，也不能混用 regional 租约或 serverless 网关配置。主站入口需要允许 `POST /internal/sites/sync` 和 `POST /internal/sites/events`（含 gzip），以及普通模型端点。反向代理 SSE 关闭 buffering，不要对流式输出套 gzip 缓冲。主站可信代理配置按实际从站出口地址设置，避免错误地信任任意来源的客户端 IP 头。

ecosserver 不加配置也保持 `standalone`；也可明确设置：

```yaml
site:
  mode: standalone
```

## 恢复与运维

- 从站数据库记录固定站点身份，重启后不能通过漏配 `site.mode` 把从站变成独立账本。使用新数据库重建/更换身份；保留旧库以补交未确认事件。
- 主站不可达超过有效期时只停止新请求，不能清空从站数据库或 outbox；恢复连接后会继续补交，完成同步才恢复就绪。
- `site_outbox` 是从站待上传事件；`site_receipts` 是主站幂等凭据；`site_replica_rows` 是主站基线。不要手动删除这些表中的数据作为“修复缓存”。
- 诊断记录进入主站已有 Ops/连接记录，usage 进入已有使用记录。主站请求 ID 加从站命名空间避免碰撞，客户端及上游请求标识保留。连接诊断 `detail.site_node_id` 可识别来源。主站会把从站连接跟踪关联到已导入的账单，供使用记录的详细耗时和平均耗时统计读取；账单、跟踪乱序到达会自动补关联，重复上报不增加样本。
- 账单回执及无法分类的旧 `site_receipts` 永久保留，随数据库备份。新版诊断回执和映射随对应历史的保留期回收，主站记录不可回退的时间边界，过期重传只确认、不重建已清理日志。拒收证据不在这项回收范围内。
- 从站只启动现有每日清理器的本地历史计划，读取同步的 `data_retention` 与请求日志保留期；不启动 Key 风控、全局统计或账号维护。只清理过期本地日志和已结算账务历史，outbox、待处理拒收、站点身份和配置基线保留。仍有未确认或拒收账单的请求，其用量、计费事件和去重记录受保护；用量保留无限期或用量清理失败时，不回收去重记录。
- 主站每日分批回收配置投影的删除标记，并原子保存最早可增量恢复的版本。正常在线从站继续增量；离线游标早于回收边界时重新安装完整快照，不能漏掉账号撤权或 Key 删除。清理跳过正在发布的节点，不排在发布锁前等待。
- 同步消息解压后每页上限 32 MiB。初次快照可分多页安装，最长允许 2 分钟；期间不放行请求。安装成功后仍按本轮请求发出的时间计算租约，不从安装结束时重新增加 20 分钟；若响应已超过租约有效期，必须再完成一轮新鲜同步才恢复服务。
- 无法导入的事件在两端 `site_rejected_events` 保存原始载荷、原因和状态。时钟超前、账号/订阅缺失、外键及唯一约束依赖问题标为 `retrying`，从站原账单留在 outbox，按 30 秒至 15 分钟退避重试，最多 20 次后转人工对账，不占用待核对回执窗口；其他事件继续处理。确定性错误标为 `pending` 并保留拒收回执。两类账单均保留从站原扣款覆盖；恢复入账或管理员明确结清/免收后，终态随余额同一快照下发，原叠加随之撤销。不要直接删除隔离记录作为退款。
- 主站账单提交后的缓存失效错误只记录告警，由现有持久计费恢复 worker 重试；不会把已成功提交的账单返回为同步失败。
- v6 与更旧控制协议不混用。新主站兼容已验证的旧 v6 程序；其他未知契约或破坏性变化仍拒绝安装，从站按其运行版本的有效期停止新请求。将有效期从 60 秒延长到 20 分钟不改变同步协议，只需更新从站程序；尚未更新的从站仍执行其原有有效期。独立站点不受影响。
- 当前没有部署切换脚本或自动生产发布；启用时先部署匹配协议版本到主站，再配置从站，确认同步、三协议调用、最后一次成功同步的请求发出 20 分钟后拒绝新请求和恢复后的补账。

## 使用记录的会话与请求来源

`usage_logs.client_context` 是可选展示字段，记录入口客户端明确上报的会话、线程、父线程、代理、父代理、轮次与请求用途。每个标识最多 255 字节，不保存完整 headers、提示词、设备 ID 或密文历史，不参与鉴权、路由或扣费去重。HTTP 与 WebSocket 每轮分别捕获；未提供的角色保持未知，不能根据提示词或缓存键推断主子代理。

从站本地处理的记录随既有 `sub2api.site.events.v1` 账单事件上报 `usage.client_context`，无需改变配置投影或协议版本。新主站接收旧从站遗漏的字段时保留 NULL；旧程序忽略新增可选字段。部署仍先主站后从站。转发请求保留入口元数据，由主站记录，不在从站重复入账。历史无代理元数据的记录只能展示已有会话 ID 与客户端，无法补回父子关系。

## 主站先切换的升级约定

每次 rebase 的字段清单、双向兼容测试和性能对照要求以 [分支维护指南](DEV_YWLCODE.md#主从站的字段兼容要求) 为准。配置字段固定在 `repository/site_contract_fields.go`，配置契约为 `sub2api.site.config.v1`，账单和诊断契约为 `sub2api.site.events.v1`，二者不再依赖物理表的整体 schema 指纹。

- 同步字段固定，独立于整张物理表。每次上游变化都识别新增/删除/改名/类型或语义变化，明确是否参与同步；路由需要的字段还必须接入从站调度和缓存失效。
- 先切换主站，旧从站忽略新增可选配置字段并按兼容的旧语义继续工作。新主站接收旧从站不完整的可选请求明细时使用明确默认值或忽略；缺失与显式 `null` 分开处理。必需的身份、权限及扣费依据仍要严格校验。
- 再切换从站，自动补齐并应用新增字段。旧版本已推进的增量游标不能使新版本永久漏掉新增字段；全量恢复或投影版本机制需要覆盖此场景。
- 配置和账单事件分别判断兼容性。升级不应阻塞格式兼容的历史账单，补默认值不得改变原始事件摘要、回执和扣费去重。不能执行的新权限/路由规则要有明确的启用时机及不兼容处理。
- 在独立实验环境验证混跑、单方宕机、断网续租、重复上报及恢复，并做升级前后性能对照；不得用生产数据或生产链路注入故障。

升级自旧 v6 时，主站识别已验证的旧 schema 并输出旧字段/策略格式，继续接收旧账单。旧从站无法执行新 Key 上下文上限时，将该 Key 的路由摘要设为不可匹配值，请求带原 Key 转交主站执行上限检查；主站 Key 状态不变。Qwen 账号、启用新计数/流阶段冷却规则的账号，暂不在旧从站调度，模型请求转发主站。启用新的 12 小时缓存写入渠道价格时，旧从站的 OpenAI 账号也暂交主站处理；其他平台不受这项定价保护影响。从站升级后，投影 epoch 自动变化，全量补齐字段并恢复相应授权。详见 [2.21.5 升级记录](REBASE_2.21.5.md)。

完整发布仍先验收 ecosserver 独立站，再按 boscserver 主站、配对从站的顺序切换，见 [部署顺序](README.md#强制部署顺序双机上传先-ecosserver后-boscserver)。回退前也要核对已升级数据库、协议和未结算账单的兼容性。

## 差网络下的行为

模型转发保留 HTTP/2 多路复用，并使用与 OpenAI 上游相同的连接探测：连续 15 秒没有收到帧时发 PING，再等 15 秒无应答则由 Go 关闭失效连接，后续请求重新建连。PING 检查连接活性，不要求模型每 15 秒输出 token。单条流的超时或 `RST_STREAM` 只结束该请求，不主动关闭其他在途请求共用的连接池。普通上游、SOCKS5/SOCKS5H 上游拨号和主从连接均使用 TCP 保活（15 秒空闲、5 秒间隔、3 次探测）；Linux 另设置 30 秒 `TCP_USER_TIMEOUT`，限制未被确认的数据。健康长流没有总时长上限。这些连接共用保护代码，但连接池仍相互隔离。

从站转发另有三项本节点配置，均可设置为 `0` 关闭对应阶段上限。它们不下发给其他站点，不改变同步租约、国内模型处理或主站现有上游阶段策略：

| 配置（`site` 下，单位秒） | 默认值 | 计时范围 |
| --- | --- | --- |
| `forward_upload_idle_timeout_seconds` | 120 | 开始转发后，上传正文连续无读取进展；读取新正文会刷新期限，写完后结束 |
| `forward_response_header_timeout_seconds` | 600 | 请求写完后等待响应头，收到响应头即结束；也覆盖 WebSocket 升级握手 |
| `forward_response_idle_timeout_seconds` | 600 | 单次等待主站响应正文读取的最长时间；不计下游接收慢造成的暂停，不限制持续输出的总时长 |

环境变量分别为 `SITE_FORWARD_UPLOAD_IDLE_TIMEOUT_SECONDS`、`SITE_FORWARD_RESPONSE_HEADER_TIMEOUT_SECONDS`、`SITE_FORWARD_RESPONSE_IDLE_TIMEOUT_SECONDS`。正常 SSE 心跳也属于响应字节；若主站在长思考或非流式任务中可能连续 10 分钟完全不返回响应头或正文，应按实际业务调大对应上限，或设为 `0`。WebSocket 升级成功后保留双向读写，不应用 HTTP 正文空闲上限；TCP 失联检测继续生效。

模型转发不增加生成请求重试：连接断开或超时后，即使还没输出，也不能证明主站尚未执行或计费。HTTP 200 后中断继续表现为中断流，不拼接第二次生成、不补造成功终态。下一条独立请求可使用新连接；Go 自带的协议级安全重试仍由 Go 管理。同步和账单则继续依靠各自的幂等/去重规则重试。`site primary forwarding failed` 日志记录请求 ID、阶段、协议、是否复用连接、请求是否写完及响应读取字节数；不写入 URL、Key 或请求正文。`http2_connection_error` 提供连接级分类，不能单独把它当作某个用户请求的最终失败证据。

从站的配置同步/续租、账单及诊断事件上报、模型转发分别使用独立 HTTP 连接池。配置同步使用 **5 套独立的 HTTP/1.1 keep-alive 连接池**，每套最多持有一条连接。正常同步依次轮换，每 5 秒仍只发起一轮，通常每条连接约 25 秒复用一次，不把正常同步流量放大 5 倍。网络超时、读响应中断或主站临时错误时，淘汰故障池的空闲连接并尝试下一套，单轮最多两次；失败后的下一轮从后续连接池继续，不重新回到刚失败的前两套。因此可以连续尝试第 1、2、3、4、5 套，同时维持每轮的耗时上限。不并行安装快照，部分响应不安装，认证或协议数据错误也不通过重复请求掩盖。HTTP/1.1 请求取消会关闭对应 TCP 连接，避免反复在一条停滞的 HTTP/2 会话上创建新流。

账单及诊断上报逐批串行，另有一套 HTTP/1.1 连接池，保留正常批次的 keep-alive，超时取消后重连。模型转发继续使用原有独立连接池及 HTTP/2 支持；国内模型请求使用原有上游连接池。停止站点管理器时关闭各池的空闲连接。5 个同步池不固定 DNS 地址，继续执行 20 分钟租约或账单确认规则。它们防护单连接故障，不等于独立网络出口：要抵御整条线路中断，还需运营层提供通往同一主站的独立网络路径。

`site event transfer finished` 记录批次条数、gzip 后字节数、耗时、协议、连接两端地址、是否复用及最后传输阶段，不记录凭据或事件正文。同步失败另记录 `site synchronization transfer failed` 的相同连接与阶段信息；切换连接时记录 `site synchronization retrying on alternate connection`。传输成功只表示收到并解析响应，后续仍须校验回执并持久确认；应结合 outbox、拒收记录和去重凭据判断是否完成结算。此传输调整不改变主从数据契约，可单独更新从站应用，无需重启主站、数据库或 Redis。

权限同步与事件上传各使用一个后台循环。权限同步正常每 5 秒一轮，增量同步每次网络尝试最多 12 秒，整轮（包含另一连接的重试及本地安装）最多 24 秒。失败或租约过期后仍持续尝试，不等待用户访问。慢请求不会与下一轮重叠；超过一个周期时最多立即补做一轮，不会为每个用户请求额外发同步 RPC。首次全量同步单次网络尝试最多 90 秒，整轮最长 2 分钟，因此初始化期间不保证每 5 秒重新连接。租约仍从整轮最初发起时计时，重试不重置租约起点。TCP 重传可修复部分丢包，gzip 减少控制面和 GPT 请求体的字节数，但不能消除线路丢包。

20 分钟是权限副本的严格上限。持续延迟或严重丢包使同步无法及时完成时，从站会自动拒绝新的 DeepSeek 和 GPT 请求，恢复成功后自动放行。连接恢复后的耗时包括当前失败请求的剩余超时、下轮同步等待和安装耗时，不能承诺网络恢复即刻可用。已放行的国内流式请求继续使用独立的国内上游链路，完成后计费持久化；GPT 请求本身依赖主站链路，仍可能变慢或中断。

上报请求已被主站提交、但确认响应丢失时，从站保留事件并重发，主站凭据去重。上传连续处理最多 512 条/批，不等待下一次 5 秒轮询；主站每 64 条分段提交，后段超时不回滚已完成段，丢失确认后仍凭永久账单回执去重；权限租约失效不妨碍后台结算已完成的请求。有积压而上传失败时，每次请求结束后等待 500 毫秒重试，单次上传超时 30 秒；没有积压时不发送上传请求。旧版本遗留的超大未确认账单会先分批核对，核对完成前不发放新租约。账单在发送前持久标记，权限同步只暂停新一批上传的准备，已在传输的批次可以继续；因此慢上传不拖住续租，且快照中的余额与回执保持一致。错误、请求诊断和账单都占事件条数，恢复时间仍取决于实际积压及链路/数据库能力；补交事件的数据量与权限增量分开计算。不要清空 outbox。

## 代码接入与本地复现

主从站协议及网关入口放在 `internal/site/`；数据库复制/事件导入分别在 `repository/site_store.go`、`site_events.go`；配置校验和服务接线分别在 `config/site.go`、`server/sites.go`；缓存与价格同步在 `service/site_sync.go`。原有文件只保留配置字段、初始化调用和必要的从站隔离判断。默认独立模式的同步路径明确返回 404，不安装从站捕获 trigger，原有模型请求处理继续使用原路径。

后续 rebase production 应检查新 migration 的完整文件名、Wire 接线、网关中间件顺序、后台任务和计费入口。请求计时中间件必须先于从站入口，避免漏算读取正文的时间。新增授权/路由字段与表时，按上述固定字段契约审查同步、默认值、读取和缓存，完成升级前后性能对照。已执行过的数据库 migration 不可直接改名或改内容。

可复现的 Docker 故障实验见 [tests/site-lab/README.md](tests/site-lab/README.md)。它运行真实两套 Sub2API 和数据库，但使用模拟模型上游，不代表真实模型质量、跨洋吞吐或大型用户库容量结果。

## 拒收账单对账

以下接口仅在主站注册，使用现有管理员认证、权限和审计中间件。站点配对令牌不能调用管理接口。

- `GET /api/v1/admin/sites/:node/rejections?state=pending&after=0&page_size=100`：按事件 ID 分页查看；可筛选 `pending`、`retrying`、`settled`、`waived`。列表不返回原始载荷。
- `GET /api/v1/admin/sites/:node/rejections/:event`：查看原始载荷、原因、次数、处理备注和操作者。
- `POST /api/v1/admin/sites/:node/rejections/:event/resolve`：JSON 正文为 `{"action":"retry","note":"已修复缺失的订阅，重试原账单"}`。

`action` 的语义：

| 操作 | 作用 |
| --- | --- |
| `retry` | 以原始账单重新入账，保留原计价和幂等标识。仍不具备入账条件时返回 409，并保留原状态；成功后变为 `settled`。可用于处理旧版本留下的永久拒收记录。 |
| `settled` | 管理员已在主站完成并核实手工补扣，以备注记录依据；此操作不再次扣钱，只结清事件并撤销从站叠加。 |
| `waived` | 管理员明确决定免收；不扣主站余额，撤销从站的原账单叠加。 |

必须提供非空 `note`。终态重复提交相同操作幂等，冲突操作返回 409。原始载荷、原因和处理记录保留。处理结果通过 `$settlements` 元数据与余额/额度在同一快照安装，丢失响应、进程重启和迟到的拒收消息不会重新叠加已处理账单。等待主从下一次成功同步后，从站才反映处理结果。

时钟超前的旧账单不会被静默改写时间；应等待该时间符合主站校验，或核实后手工结清/免收。永久删除的归属数据同样需要修复依赖或人工对账，系统不会把订阅账单擅自改成余额收费。

## v6 回执恢复与数据库迁移

已有从站升级后保留原事件命名空间及所有待上报账单；全新从站数据库生成持久 UUID，与配置的节点 ID 共同标识事件世代。搬迁从站时应整体迁移数据库，保留 `site_identity`，不能只复制配置后重建数据库并把它视为原站点。普通重启不会改变 UUID。

账单确认同时比对事件编号和原始载荷的 SHA256 摘要。相同世代内编号意外复用时，保留两份冲突证据，其他账单继续处理。冲突证据位于 `site_event_conflicts`；普通拒收仍通过管理对账接口处理。账单与诊断分事务导入，诊断失败不回滚已经提交的扣费。

已收到上传确认，但两分钟后仍没有出现在主站一致性快照中的账单会恢复重传；现存计费幂等记录防止重复扣费。这能恢复仍在 outbox 中的账单，**不保证任意主站数据库时间点回滚之后找回已从 outbox 删除的记录**；此类灾难恢复需要数据库备份和人工账务对账。

结清或免收结果与余额同一快照下发。只有从站回传已安装的版本后，主站才停止重复投影这些结果；已确认对账证据保留 90 天后分批清理，去重回执继续保留。未处理、未确认账单和冲突证据不会自动删除。

触发器在无导出节点时直接返回，热表仅比较所需字段。删除配对配置目前不会自动物理删除 `site_export_nodes`，旧世代投影也保留；移除废弃节点需在确认无在途同步、未结算账单后维护，避免与计费事务并发清理时丢变更。

### 从站出口代理

在主站 **系统设置 → 常规 → 从站出口代理**，按已配对的从站分别保存“从站处理代理”和“从站转发同步代理”。前者用于本地模型上游，后者用于转发、同步及事件上报。只接受带端口的 HTTP(S) 代理地址，不接受账号密码、路径或查询参数。主站、独立站及其他从站不使用该节点的配置。HTTPS 目标通过 CONNECT 保持原证书校验。普通账号代理不替代配置好的本地处理出口。

从站可用 `SITE_PROCESSING_PROXY_URL` 和 `SITE_FORWARD_PROXY_URL`（Compose 须显式传入）指定启动默认值。面板留空使用对应默认值；两者均未配置时保留原部署行为。新设置随下一次认证并成功安装的同步生效，新请求选新出口，已开始的请求可以完成。不要求改主站域名、供应商名单或重启。若填错转发代理，只有同步重试可以使用明确指定的启动转发代理取回修正；不会改用处理代理或自动直连。需要绝对禁止其他出口的部署还须通过宿主机防火墙阻断从站直连及其他宿主机代理。

两个地址按从站 ID 存在主站 settings 中，只在该已认证从站主动声明支持时作为同步响应可选字段发送。旧从站不接收；新从站与旧主站通信时使用本机配置。配置不进入公共设置或其他站点的投影，无数据库迁移或账单契约变更。
