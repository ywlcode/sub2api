# 主站、内网从站、主站无从站

三种模式共用 Sub2API 程序，配置为 `site.mode`：

| 模式 | 配置值 | 行为 |
| --- | --- | --- |
| 主站无从站 | `standalone`（默认） | 原有完整站点，不开放从站同步接口 |
| 主站 | `primary` | 原有完整站点，向配置好的从站发布权限和路由，接收用量及诊断数据 |
| 从站 | `secondary` | 国内模型本地鉴权、路由和计量，其他请求保留原 Key 转发主站，不提供管理后台 |

计划中 boscserver 配置 `primary`，ecosserver 保持 `standalone`。两者的用户、余额与订阅账本独立。从站只与 boscserver 配对，不会自动切换到 ecosserver。

## 数据与请求路径

每个从站 ID 当前运行一个服务进程。从站需要自己的 PostgreSQL、Redis 和数据目录，不能连接主站数据库或共享主站 Redis。当前实现复用完整网关及数据库结构，以保留三种协议、火山兼容、权限、订阅、计费行为；不是只运行一个无数据库代理。

在主站的账号创建/编辑页面，为持有独立 API Key 的账号开启 **允许从站直接处理**（默认关闭）。该开关授权已配对的从站取得账号凭据并处理其支持的模型；无需额外维护账号 ID 或模型分流清单。它是额外处理权限，**主站直接收到请求时仍可正常调度该账号**，开关不会修改账号状态、调度开关或主站分组绑定。主站无从站模式下也不影响原有请求处理。

从站根据已同步账号的模型映射、默认模型、通配模式以及当前 Key 所属分组和组合路由判断处理位置；匹配后继续走现有本地网关：鉴权、IP 限制、Key 与分组权限、余额/订阅/Key 额度检查、本地上游调度、协议处理、用量计算。开关本身不会赋予用户调用权限。账号保存后在下一轮同步生效，正常约 5 秒，无需重启主从站。关闭开关后，新请求改为转发主站；已放行的请求可以完成，撤销前的账单仍能补交。影子账号和 OAuth 账号不支持此开关。

其他模型由反向代理转发主站：原用户 Key 保留，JSON 正文达到 1 KiB 且 gzip 压缩有效时使用 gzip；已有压缩正文保持原编码。主站完成鉴权及计费，从站不重复生成此类请求的正式账单。SSE 及时 flush，WebSocket 升级整体转发主站，从站不解析 WS 帧，因此国内请求应使用 HTTP 三协议入口。

从站本地鉴权缓存 Key、用户、分组和模型权限配置，TTL 为 30 秒，最多 2,048 条，缓存内容合计最多 16 MiB；不保存原始 Key。每次鉴权及并发准入复核仍通过一条轻量 PostgreSQL 查询读取本地副本中的余额、Key 已用额度、到期时间及禁用/删除状态，不以缓存代替实时额度检查。权限配置同步在数据库提交前后主动失效缓存，并阻止旧查询回填；安装期间回退完整实时查询，普通心跳和纯用量同步不清空身份缓存。订阅用量、计费、并发槽位及 60 秒主站租约继续使用原有检查。

鉴权数据库查询上限仍由 `api_key_auth.lookup_concurrency` 控制（默认 64）。达到上限后，最多允许额外 512 个鉴权操作等待，最长 5 秒；调用方取消或更短的准入超时会提前结束等待，队列已满或等待超时返回 503。这不是用户/账号并发额度，也不延长主站配置租约。主站及独立站继续使用原有 L1/Redis 鉴权缓存和未命中保护。

从站每 **5 秒**同步一次。首次全量、后续返回行级 diff（包括删除）；主站进程重启保留数据库中的增量游标；游标或配对配置不匹配时返回全量，分多页传输。数据库列结构不一致会拒绝同步，升级需要两端使用匹配的程序版本。

每次同步成功安装后产生 **60 秒（1 分钟）**有效期，起点是该次请求发出时间，使用本进程单调时钟。失败、错误响应、安装失败均不续期。首次同步前、重启后未同步、到期后，从站所有新的模型请求返回 **503**（包括转发主站的 GPT 请求）。`/health` 保持存活，`/readyz` 表示同步就绪。已放行请求可继续完成，后台持续尝试恢复同步，不存在额外离线宽限期。断连期间主站停用 Key、撤销账号授权等变化，最迟在这次有效期结束时由从站停止接受新请求；主站自身服务不依赖从站租约。

单纯租约过期或同步请求失败不会清空配置基线和增量版本号。主站恢复后，未重启的从站继续获取断连期间变化的行，同一行多次更新只传最新投影；无需因为过期而重新下载全部配置。首次启动、从站重启、版本/配对配置不匹配或安装失败后才需要全量恢复。主站只重启进程且保留数据库和配对配置时，仍可继续增量。

国内请求的用量通过原有持久计费日志落盘，并与本地扣费、上报 outbox 在同一事务提交；已识别 Key 的错误及连接诊断记录在写入时进入 outbox，未鉴权请求的诊断仅保存在从站。主站使用事件 ID 和账单幂等键去重，消费与确认记录在同一事务提交。未确认消费在安装主站快照后重新覆盖到本地余额/额度。确认使用具体事件 ID，避免并发提交、丢失响应导致跳过消费或重复扣费。主站延迟收到订阅用量时按原记录时间及北京时间日/周/月边界入账，不占用已经进入的新周期。这里的原记录时间沿用网关生成用量记录的时间；不是重新定义为请求开始时间。计价沿用现有网关，已生成的账单金额在补报时不重新定价。从站缺少 usage 或定价时会持久记录 `billing/site_usage_unsettled` 并上传供核对，不生成虚假的零费用成功账单；此类记录本身不表示客户端收到 HTTP 错误，也不能在没有可靠用量时自动补算费用。

原有账号/用户/Key 并发与 RPM 在各站本地执行，**不是跨站强一致全局并发上限**。余额、额度存在同步窗口，允许短时间超额；未完成请求的最终费用也可能在之后才入账。

主站下发账号凭据、权限投影和有效价格目录。用户 Key 使用每个从站独立 HMAC 投影，不下发可复用明文 Key；用户登录密码、TOTP、支付配置及未授权账号的凭据不下发。同步接口仅供受信从站，持有配对 token 的从站能够代表主站执行国内调用和提交计费。使用 HTTPS 及独立的随机 token，配置文件按密钥文件管理。

## 请求配置同步范围

当前控制协议为 v5，两端必须使用匹配的程序。同步契约集中在 `service/site_policy.go`、`config/site_gateway_fields.go`、`repository/site_store.go`，不依赖在每个管理接口中发送通知。

- 22 张业务表的投影：用户与并发/RPM/平台限制、Key 与 IP/模型限制、分组与个人覆盖、订阅与实际额度、获准账号与模型映射、组合路由、渠道计价与峰谷时区、错误透传、账号引用的 TLS 指纹等。
- 72 个全局请求设置：协议转发、客户端兼容、默认/回退模型、重试与冷却、调度策略、搜索模拟、错误采集等。账号状态还合并性能监控和 AI 运维的暂停结果；暂停控制器和任务本身仍留在主站。
- 118 个网关配置叶子及有效计费/额度默认值：请求体和上游响应限制、流超时、重试预算、请求协议策略、最低余额预留、请求中资金预留、Gemini 额度默认值等。复制主站实际加载的值；主站 YAML 修改仍需按既有方式重新加载/重启，随后从站可自动接收。
- 有效价格目录，以及获准账号最近 7 天完成的质量检测结果摘要。质量任务、原始检测内容不下发；从站延迟、错误率、连接和负载仍按本地链路采集。

按当前用途，从站只处理开源模型，**安全审计、内容审核、安全处罚规则及处罚状态不下发，也没有新增安全事件回传协议**。用户由管理员停用后的普通 `users.status` 仍属于鉴权数据，照常同步。GPT、Claude、Grok 等未授权本地账号的请求继续交由主站。

账号的组绑定、Key 模型映射、渠道模型别名和组合路由参与位置选择；位置判断后仍经过原有网关的完整授权与调度。仅靠客户端检测才确定的分组 fallback、无法从已授权账号直接判断的请求仍可能交主站处理，不承诺所有复杂回退场景都在从站执行。

登录注册、密码/TOTP/JWT、支付/通知、后台页面、定时任务、自动授信的执行等留主站。本地站点身份、数据库/Redis、可信代理链、连接池、worker/队列和存储路径留本站。搜索模拟的主站 `proxy_id` 被清除，从站走自己的直接网络；如供应商要求专用代理或国内不可达，需要另行配置网络，不能复制一个无对应对象的代理 ID。异步图片任务、插件安装/票据、浏览器与 BPS 等专项能力不属于本次开源文本模型从站范围，不为它们复制主站存储、任务控制器和密钥。

安装配置后同步刷新请求缓存、优先级调度规则、Ops 采集规则、搜索客户端、错误透传、TLS 与渠道缓存；请求体限制也从当前配置读取。安装或依赖刷新失败，不续租并关闭就绪，下一轮强制全量恢复。只有余额/用量变化时，不重复构建搜索和 TLS 等配置依赖；无变化心跳不重建这些缓存。

## 增量与每轮数据量

每 5 秒发起一轮，**首次、从站重启或版本不匹配时全量，之后传行级增量（含删除）**。只修改用户并发时发送该用户的一行，不发送全部用户。JSON 内某个字段变化会发送该行完整投影；有效网关默认值和价格目录各是一个合成对象，改变其中内容会发送该对象。

主站通过事务触发器维护每个从站的变更集合和持久投影。导出期间只读取变更集合和业务数据，不锁住扣费触发器；发布后用短事务和 `SKIP LOCKED` 清理本次读到的精确版本，较新的修改和未提交事务留给下一轮。多个主站实例通过独立的发布锁串行化同一从站的导出。余额、Key、订阅等常见变化只读取对应行；账号授权、分组绑定等影响授权范围的变化会重建授权投影。用户、Key、订阅和个人额度仅包含能访问已授权账号分组的用户，未授权账号凭据不下发。全量快照每页通常不超过 2 MiB 或 1,024 行；单条较大配置独立成页，单条上限 30 MiB。跨页期间投影版本变化时重新开始，不能混装不同版本。

从站日志 `site synchronization completed` 每轮记录：

| 字段 | 含义 |
| --- | --- |
| `full`, `rows` | 本轮全量/增量、下发行数（含删除） |
| `events`, `pending` | 控制请求中的事件数（v5 为 0）、本轮待核对账单 ID 数 |
| `upload_json_bytes`, `upload_wire_bytes` | 从站到主站，压缩前/gzip 后正文大小 |
| `download_json_bytes`, `download_wire_bytes` | 主站到从站，压缩前/gzip 后正文大小 |
| `duration_ms` | 本轮采集、传输、安装总耗时 |

字节统计不含 HTTP 头、TLS/TCP/IP 开销和重传。控制请求只带版本和最多 4,096 个已尝试上传的账单 ID。事件由独立上传循环连续发送，每批最多 512 条，并按 32 MiB 上限缩小批次，账单优先且为诊断保留份额。等待余额快照确认的账单达到 4,096 条时暂停增加新账单上传，诊断仍可上传；下一轮同步核对后继续。诊断积压不增加控制消息大小。上述每轮字节统计仅统计配置同步，不包含独立事件上传。

本机可复现测试 `test_config_sync.py` 验证配置增删、并发值、主站有效默认值、三协议、暂停/恢复、安全配置排除，并记录小样本与千用户样本的实测字节数。数值应结合当次用户/Key/账号/价格条数解读，不能当生产库的固定大小。

## 主从站认证

所有同步均由从站主动向主站发起，主站不需要连入公司内网：

1. 每个从站使用独立随机 token（至少 32 字符，建议 `openssl rand -hex 32` 生成），放在双方配置中，不使用管理员登录 token 或用户 Key。
2. 主站校验 `Authorization: Bearer <token>`，将其绑定到配置中的从站 ID；携带别的从站 ID 会拒绝。允许下发的账号由主站账号配置开关决定。
3. 从站校验 HTTPS 证书与域名，首次成功安装后将主站 ID 固定在本地数据库，之后拒绝身份不匹配的主站。同步请求不跟随 HTTP 跳转，避免泄露配对凭据。
4. 这不是双向客户端证书（mTLS）。主站通过配对 token 验证从站，从站通过 HTTPS 验证主站。`allow_http` 仅用于已另行加密的私有隧道或本地测试，生产公网保持 `false`。
5. 撤销从站时从主站 `peers` 移除并重载部署配置；从站最迟在最后一次成功同步的请求发出起 60 秒后停止新请求。轮换 token 需更新两端，会重新生成用户 Key 的 HMAC 投影；同步成功前保持关闭。更换主站身份需使用新从站数据库，不能靠修改 ID 绕过绑定。

GPT 等透传请求仍用用户原 Key，配对 token 不附加到模型请求中。配对 token 不适合交给普通用户，它授权从站取得国内上游凭据并提交账单。

## 配置示例

在 boscserver 原有配置中增加（示例 ID、账号号、token 需替换）：

```yaml
runtime:
  role: full
site:
  mode: primary
  id: bosc
  peers:
    - id: office
      token: "REPLACE_WITH_UNIQUE_RANDOM_TOKEN_AT_LEAST_32_CHARS"
      base_urls:
        54: "https://ark.cn-beijing.volces.com/api/v3"
```

先在主站账号 54 开启“允许从站直接处理”。`base_urls` 是可选的、此从站专用上游地址覆盖，不能单独授权下发账号。若主站账号指向美国 go 中转，必须在这里改成国内直连地址。覆盖会清除该从站账号继承的 `api_base_urls`，由现有协议选择逻辑推导；火山 Messages 自动使用 `/api/compatible/v1/messages`。国内账号的美国代理 `proxy_id` 不会下发使用。账号原有火山兼容开关及模型映射保持主站配置。

从站先用原部署方式初始化一套独立 PostgreSQL/Redis；允许只有自动安装创建的管理员，不能含其他用户、Key、账号或账单。挂载自己的持久目录和 `config.yaml`：

```yaml
runtime:
  role: full
site:
  mode: secondary
  id: office
  primary_url: "https://YOUR_BOSC_ORIGIN"
  token: "REPLACE_WITH_THE_SAME_OFFICE_TOKEN"
  allow_http: false
```

简单字段也可以用 `SITE_MODE`、`SITE_ID`、`SITE_PRIMARY_URL`、`SITE_TOKEN` 配置；主站 `peers` 推荐使用 YAML。从站不能启用 simple 免计费模式，也不能混用 regional 租约或 serverless 网关配置。主站入口需要允许 `POST /internal/sites/sync` 和 `POST /internal/sites/events`（含 gzip），以及普通模型端点。反向代理 SSE 关闭 buffering，不要对流式输出套 gzip 缓冲。主站可信代理配置按实际从站出口地址设置，避免错误地信任任意来源的客户端 IP 头。

ecosserver 不加配置也保持 `standalone`；也可明确设置：

```yaml
site:
  mode: standalone
```

## 恢复与运维

- 从站数据库记录固定站点身份，重启后不能通过漏配 `site.mode` 把从站变成独立账本。使用新数据库重建/更换身份；保留旧库以补交未确认事件。
- 主站不可达超过有效期时只停止新请求，不能清空从站数据库或 outbox；恢复连接后会继续补交，完成同步才恢复就绪。
- `site_outbox` 是从站待上传事件；`site_receipts` 是主站幂等凭据；`site_replica_rows` 是主站基线。不要手动删除这些表中的数据作为“修复缓存”。
- 诊断记录进入主站已有 Ops/连接记录，usage 进入已有使用记录。主站请求 ID 加从站命名空间避免碰撞，客户端及上游请求标识保留。连接诊断 `detail.site_node_id` 可识别来源。主站会把从站连接跟踪关联到已导入的账单，供使用记录的详细耗时和平均耗时统计读取；账单、跟踪乱序到达会自动补关联，重复上报不增加样本。
- `site_receipts` 当前不自动裁剪，以保证历史补报不重复；需随数据库备份保留。从站关闭管理类后台任务，当前也不自动裁剪本地账单和同步凭据，需监控本地磁盘容量。
- 同步消息解压后每页上限 32 MiB。初次快照可分多页安装，最长允许 2 分钟；期间不放行请求。如果安装结束时已超过 60 秒，必须再完成一轮新鲜增量才恢复服务。
- 无法导入的事件在两端 `site_rejected_events` 保存原始载荷、原因和状态。时钟超前、账号/订阅缺失、外键及唯一约束依赖问题标为 `retrying`，从站原账单留在 outbox，30 秒后重试，不占用待核对回执窗口；其他事件继续处理。确定性错误标为 `pending` 并保留拒收回执。两类账单均保留从站原扣款覆盖；恢复入账或管理员明确结清/免收后，终态随余额同一快照下发，原叠加随之撤销。不要直接删除隔离记录作为退款。
- 主站账单提交后的缓存失效错误只记录告警，由现有持久计费恢复 worker 重试；不会把已成功提交的账单返回为同步失败。
- v5 与旧控制协议不混用；升级主站和从站到匹配协议版本，升级间隙从站按其运行版本的有效期停止新请求。将有效期从 15 秒延长到 60 秒不改变同步协议，只需更新从站程序。独立站点不受影响。
- 当前没有部署切换脚本或自动生产发布；启用时先部署匹配协议版本到主站，再配置从站，确认同步、三协议调用、最后一次成功同步的请求发出 60 秒后拒绝新请求和恢复后的补账。

## 差网络下的行为

权限同步与事件上传各使用一个后台循环。权限同步正常每 5 秒一轮，常规单次总超时 12 秒。失败或租约过期后仍持续尝试，不等待用户访问。慢请求不会与下一轮重叠；超过一个周期时最多立即补做一轮，不会为每个用户请求额外发同步 RPC。首次全量同步单次最长 2 分钟，因此初始化期间不保证每 5 秒重新连接。TCP 重传可修复部分丢包，gzip 减少控制面和 GPT 请求体的字节数，但不能消除线路丢包。

60 秒是权限副本的严格上限。持续延迟或严重丢包使同步无法及时完成时，从站会自动拒绝新的 DeepSeek 和 GPT 请求，恢复成功后自动放行。连接恢复后的耗时包括当前失败请求的剩余超时、下轮同步等待和安装耗时，不能承诺网络恢复即刻可用。已放行的国内流式请求继续使用独立的国内上游链路，完成后计费持久化；GPT 请求本身依赖主站链路，仍可能变慢或中断。

上报请求已被主站提交、但确认响应丢失时，从站保留事件并重发，主站凭据去重。上传连续处理最多 512 条/批，不等待下一次 5 秒轮询；权限租约失效不妨碍后台结算已完成的请求。有积压而上传失败时，每次请求结束后等待 500 毫秒重试，单次上传超时 30 秒；没有积压时不发送上传请求。旧版本遗留的超大未确认账单会先分批核对，核对完成前不发放新租约。账单在发送前持久标记，权限同步只暂停新一批上传的准备，已在传输的批次可以继续；因此慢上传不拖住续租，且快照中的余额与回执保持一致。错误、请求诊断和账单都占事件条数，恢复时间仍取决于实际积压及链路/数据库能力；补交事件的数据量与权限增量分开计算。不要清空 outbox。

## 代码接入与本地复现

主从站协议及网关入口放在 `internal/site/`；数据库复制/事件导入分别在 `repository/site_store.go`、`site_events.go`；配置校验和服务接线分别在 `config/site.go`、`server/sites.go`；缓存与价格同步在 `service/site_sync.go`。原有文件只保留配置字段、初始化调用和必要的从站隔离判断。默认独立模式的同步路径明确返回 404，不安装从站捕获 trigger，原有模型请求处理继续使用原路径。

后续 rebase production 应检查新 migration 编号、Wire 接线、网关中间件顺序、后台任务和计费入口。请求计时中间件必须先于从站入口，避免漏算读取正文的时间。新增授权/路由字段与表时也需检查投影白名单及 schema 校验；不同 schema 不会静默继续同步。已执行过的数据库 migration 不可直接改名或改内容。

可复现的 Docker 故障实验见 [tests/site-lab/README.md](tests/site-lab/README.md)。它运行真实两套 Sub2API 和数据库，但使用模拟模型上游，不代表真实模型质量、跨洋吞吐或大型用户库容量结果。

## 拒收账单对账

以下接口仅在主站注册，使用现有管理员认证、权限和审计中间件。站点配对令牌不能调用管理接口。

- `GET /api/v1/admin/sites/:node/rejections?state=pending&after=0&page_size=100`：按事件 ID 分页查看；可筛选 `pending`、`retrying`、`settled`、`waived`。列表不返回原始载荷。
- `GET /api/v1/admin/sites/:node/rejections/:event`：查看原始载荷、原因、次数、处理备注和操作者。
- `POST /api/v1/admin/sites/:node/rejections/:event/resolve`：JSON 正文为 `{"action":"retry","note":"已修复缺失的订阅，重试原账单"}`。

`action` 的语义：

| 操作 | 作用 |
| --- | --- |
| `retry` | 以原始账单重新入账，保留原计价和幂等标识。仍不具备入账条件时返回 409，并保留原状态；成功后变为 `settled`。可用于处理旧版本留下的永久拒收记录。 |
| `settled` | 管理员已在主站完成并核实手工补扣，以备注记录依据；此操作不再次扣钱，只结清事件并撤销从站叠加。 |
| `waived` | 管理员明确决定免收；不扣主站余额，撤销从站的原账单叠加。 |

必须提供非空 `note`。终态重复提交相同操作幂等，冲突操作返回 409。原始载荷、原因和处理记录保留。处理结果通过 `$settlements` 元数据与余额/额度在同一快照安装，丢失响应、进程重启和迟到的拒收消息不会重新叠加已处理账单。等待主从下一次成功同步后，从站才反映处理结果。

时钟超前的旧账单不会被静默改写时间；应等待该时间符合主站校验，或核实后手工结清/免收。永久删除的归属数据同样需要修复依赖或人工对账，系统不会把订阅账单擅自改成余额收费。
