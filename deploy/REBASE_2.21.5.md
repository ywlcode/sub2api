## 字段和语义分类

## 验收口径

独立实验使用 `sub2api-rebase-2215`，与生产从站、旧实验分离。应用各 2 CPU / 8 GiB；两版数据库连接池统一 64 open / 32 idle。新旧对照采用 400 个合成用户、100,000 个常用英文词输入、3,000 词模拟输出及固定 1.5 秒上游等待，模拟 usage 为 100,000/3,000 tokens。这不是模型 tokenizer 精确生成的 100K tokens，也不是公网模型速度测试。

记录主站直连、从站本地、从站 gzip 转发三路径；成功必须有非空首内容和唯一正常终态。预热后要求无业务失败；首内容 P95 若增加超过 10%，需重复同条件测量并定位，不能直接宣称无退化。冷启动另列，区分有界准入拒绝与已接纳请求失败。检查 CPU、内存、数据库提交/回滚、租约、积压以及同步原文/压缩字节。200 及以上并发的压测不与编译/全量单测并行。

兼容验收包含真实旧从站二进制接新主站、旧账单新字段默认值、未知物理列、升级后新增权限实际生效；故障验收包含丢 ACK、事件分页、进程退出、60% 丢包、完全断流、超时迟到响应、租约到期、身份/schema 错误及恢复。每次故障后的余额与用量增量、主从最终余额和明细条数必须一致。

真实客户端使用隔离配置与合成文件，记录工具调用、工具结果、人工/自动压缩和压缩后续答；Codex 的 OpenAI 远程压缩与第三方摘要压缩分开验证。GPT 不测 Messages。实际协议以抓取的请求和流终态为准。

## 回退限制

本轮在隔离环境验证了旧程序直接连接升级后数据库的回退：旧版会读取新版持久投影中的未知表行，报 `unknown replica row` 并拒绝续租。恢复候选版后自动重新发布投影并恢复服务，账单和站点身份均保留。因此不能把仅替换旧镜像视为可靠回退；发布前须保留数据库备份，并按一致的程序、配置、数据库状态制定和验证回退，不能清空 outbox、回执或身份来消除错误。新主站配真实旧从站的正向升级路径已单独测试。

### 真实客户端与压缩

使用 Codex 0.167.0、Claude Code 2.1.272、OpenCode 1.19.5、dsh 0.2.2-rc.1 的独立配置、会话和合成工作目录。模型请求同时最多 5 条，客户端上下文窗口设为 32,768，降低自动压缩阈值；这部分验证工具与压缩正确性，不作为 100K 性能样本。DeepSeek 本地账号直达火山，转发账号经实验主站访问已有 bosc 服务，生产配置未改。GPT 不测试 Claude Code／Messages。

最终验收矩阵如下；每格均为 20 个用户轮次，括号为包括工具续答、摘要和客户端辅助调用在内的实际 HTTP 次数。选定成功轮次全部有完整响应，流式响应核对正常 terminal，未仅凭 HTTP 200 判断成功。

| 客户端 | DeepSeek 从站本地 | DeepSeek 转发主站 | GPT 转发主站 |
| --- | ---: | ---: | ---: |
| Codex | 20/20（43） | 20/20（41） | 20/20（41） |
| Claude Code | 20/20（45） | 20/20（43） | 不测 |
| OpenCode | 20/20（39） | 20/20（39） | 20/20（45） |
| dsh | 20/20（63） | 20/20（65） | 20/20（71） |

合计 220 个用户轮次、535 次 HTTP 调用。两次大文件工具任务逐项验证记录数、金额合计和原文件 SHA256，压缩后检查会话事实及继续调用工具。Codex GPT 的远程 v2 压缩实际通过 `/v1/responses` 的 `compaction_trigger` 输入触发，验收会话抓到 3 次触发和 3 个加密 compaction 输出，后续工具任务完成；两种 DeepSeek 配置禁用远程压缩，抓到摘要请求，未发送 `compaction_trigger`。Claude Code 和 OpenCode 的手动压缩均成功，压缩后事实检查通过。

dsh 三个会话共 86 次压缩尝试，其中 30 次成功提交摘要；56 次因客户端判定 `summary is not smaller than the shadowed content` 而保留原历史、继续当前任务。核对安装包 `dsh-compaction-basic` 后确认这是客户端替换前的大小检查及继续执行分支，所有对应 HTTP 调用正常完成，最终任务通过。不能将这 56 次宣称为成功压缩，也不能据此保证任何模型生成的摘要都有效；低阈值配置会导致频繁尝试并增加延迟。

首次完整矩阵经修正后的判定为 192/220，并非一次全过：测试 HTTPS 桥接进程发生 7 次 DNS `gaierror`，在请求到达 bosc 之前失败；随后候选主站的模型短期冷却引起部分 503。OpenCode 恢复后完成，Codex／dsh 的部分后续轮次失败。桥接重启准备过程的两次不完整复跑还遇到连接拒绝及测试账号冷却，记录均保留。仅在实验桥接中固定已经验证的 bosc IP、保留 TLS 域名校验，通过实验管理 API 解除该合成账号的网络冷却并验证模型完整响应后，重新执行受影响的 6 组；其余 5 组沿用已成功的原始证据。没有通过修改应用错误处理或生产配置消除测试失败。

dsh 初版脚本误将用户输入中的完成标记计入判定，已改为仅检查 `assistant/message` 与正常 `turn/end`，所有最终样本及原始本地 DeepSeek 样本都重新核验。原始失败、脚本修正和最终验收分别保存在 `clients/evidence/first-matrix-corrected.json`、`dsh-r5-revised-audit.json`、`final-matrix-audit.json` 及逐请求 wire 记录中。

包含探测和失败复跑期间已完成请求的最终账务共 802 条主站用量，其中 189 条从站本地用量逐请求命名空间、模型、账号、金额与主站导入记录一致；转发请求不在从站重复计费。测试用户余额两端同为 9998.06838356，等于初始 10000 减去实际费用 1.93161644，待上传事件为 0，测试用户无拒收账单。证据为 `clients/evidence/final-accounting.json`。
