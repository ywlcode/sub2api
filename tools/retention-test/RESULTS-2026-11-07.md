# 2026-11-07 本地数据保留策略验证结果

**结论：PostgreSQL 18.1 和 15.18 均通过。** 使用 `dev-ywlcode` 上的实际迁移、清理 worker
和计费仓储，基于 `0318c9936` 加本次测试及开关检查补强。没有连接、清理或部署生产数据库。

## 测试环境与样本

- 全新独立 Docker PostgreSQL，随机回环端口；测试结束后容器与数据库数据卷已删除。
- 使用 Go 1.27.3，测试仓库挂载为只读。
- 两个 PostgreSQL 版本均执行完整迁移及再次启动迁移。
- 五张高增长表各 60,000 行，覆盖 60 天；另有未完成计费、余额、请求明细、流量汇总和重复请求控制记录。
- 默认策略：诊断/耗时 3 天，完成计费/流量 7 天，去重热表 15 天、归档再保留 15 天。
- 本次只关闭临时 PostgreSQL 的 autovacuum，随后显式运行普通 `VACUUM (ANALYZE)`。

## 压缩备份与数据库占用

单位为 MiB（1,048,576 字节）。数据来自本次合成样本，**不能直接换算成生产库的预计大小**。

| 指标 | PostgreSQL 18.1 | PostgreSQL 15.18 |
|---|---:|---:|
| 清理前 SQL gzip | 109.59 | 109.59 |
| 清理后 SQL gzip | 8.69 | 8.69 |
| 备份减少比例 | 92.07% | 92.07% |
| 清理前数据库文件 | 307.14 | 305.98 |
| DELETE/归档后数据库文件 | 313.60 | 312.44 |
| 普通 VACUUM 后数据库文件 | 168.75 | 167.59 |
| 恢复到空库后的数据库文件 | 48.79 | 45.79 |

本次六张保留策略相关表的索引文件合计：清理前 **46.29 MiB**，清理归档后 **48.03 MiB**，
普通 VACUUM 后仍为 **48.03 MiB**，恢复到空库后 **4.71 MiB**。

这说明逻辑备份立即变小，但物理文件不会同比缩小；归档新增行还会短暂增加占用。
本样本部分旧数据位于连续尾页，普通 VACUUM 能截断这些空页，其他表和索引则保留空间供复用。
没有执行 `VACUUM FULL` 或 `REINDEX`。恢复到空库的尺寸不代表生产执行 DELETE 后就会达到该尺寸。

清理 worker 连同第二次幂等执行及断言，PostgreSQL 18.1 测试用例耗时 1.60 秒，15.18 耗时 1.45 秒。
这是无业务负载、约 30 万行合成数据的本地测试，不能外推生产首次清理耗时或 WAL/IO 影响。

## 本次发现和修复

首轮测试发现执行入口缺少 `Enabled` 检查。原有本机 Reload 会停止 cron，但其他实例仍可能
保留旧 cron；触发时即使刷新出已禁用的配置，也会继续删除。

在 `runScheduled` 刷新配置后、`runCleanupOnce` 开始删除前补上开关检查。
已有清理流程和 SQL 保持原样，增加真实数据库回归测试及常规单元回归测试。
已开始执行的批次不会因为这个补强被强制中止。
